# Productive layer

Major is the Chief of Staff. A milestone is a named thread. The word job
stays the live provider process. Email, social posts, and Amazon deals are
the example request an owner gives Major. This plan does not add those
connectors. The team Major raises is what would build that software.

Land on `gb/productive` from `worktrees/productive`. One commit per
milestone. Do not commit on main.

## What already exists

A channel is a named room, optionally placed in a group. A thread is the
reply chain under one root event. Its title is the participants' names.
Durable memory is `$HUSH_HOME/threads/<root>.log` and `<root>.brief`.
`GET /api/thread?root=` returns the brief and at most 32 turns.

Major leads when mentioned with other robots and emits one `` ```plan ``
fence. The relay dispatches that plan inside the same thread. Creating a
robot is `POST /api/agent` for a logged-in vibe. A robot turn is a note.
The worker rules say "No tools." Grok is started with a denylist that
blocks file and shell tools, `--max-turns 2`, and a private temp directory
as `--cwd`. Codex exec stays `--sandbox read-only`.

## Milestones

### M1. Desk record

Store `name` (64 bytes), `category` (64 bytes), and `archived` (0 or 1) in
`$HUSH_HOME/threads/<root>.desk`, mode 0600, `O_NOFOLLOW`. A missing file
means unnamed and active. Clearing the desk does not delete the transcript
or the brief. `GET /api/thread` returns the fields. `POST /api/thread`
sets them for a logged-in vibe.

Verify: `hush-c/tests/test_thread`.

### M2. Desk in the pane

The thread pane edits the name and category and can archive or restore.
A set name replaces the participant title. Archive hides that root from
the channel's active thread buttons and from the saved-thread reopen.
Archived roots stay listed so the owner can open one and restore it.
Edit `hush-c/demo/index.html` only. The relay header is regenerated by
`scripts/embed-ui.sh`.

Verify: `make test` in `hush-c` (includes `tests/check_pwa.sh` and
`tests/check_layer_ui.sh`), then name, archive, and restore in the running
hive.

### M3. Open a milestone

The owner posts one kind-1 root in the current channel, then sets the desk
on that root. The root content is the opening line. A reply still cannot
cross channels.

Verify: the new root shows under its name in the channel.

### M4. Team fence

A solo mention of Major may end in one `` ```team `` fence. Each line is
`Name | provider | one-line prompt`. The relay checks the roster cap of 16,
name clash, a printable name, and `hush_roster_is_provider`. It calls
`hush_launch_add_agent` only after the owner types Yes in that thread.
No creates nothing. Auto-approve does not skip this Yes. A robot Yes is
ignored. A bad line creates nobody.

Verify: new `hush-c/tests/test_team.c`, linked like `tests/test_thread.c`.

### M5. Hop

On a solo Major turn, the prompt gets at most 8 active milestones in the
same channel. Each line is the name, the category, and at most 200 bytes
of that root's brief. No turn bodies. Major may end with one `` ```hop ``
fence naming one milestone. The relay posts Major's note, fence removed,
as a reply to that root. A missing, archived, or other-channel name does
not post.

Verify: the index test shows no turn bodies, skips archived milestones,
and refuses another channel.

### M6. Project bind

A milestone may name one existing launch project. Only then, and only
after a separate owner Yes, may that milestone's workers use the project
path as cwd. Grok may then use `read_file`, `list_dir`, `grep`, and
`search_replace`. `run_terminal_cmd`, `web_search`, `web_fetch`, `task`,
and `Agent` stay denied. Codex stays read-only. `--max-turns` stays 2.
An unbound milestone keeps the private temp directory and the full denylist.

Verify: a bound job struct has the project cwd and the reduced denylist.
An unbound job does not.

## Out of this plan

Connectors that read mail, post to a social network, or shop. A second
coordinator beside Major. Raising `--max-turns` or opening a shell.
